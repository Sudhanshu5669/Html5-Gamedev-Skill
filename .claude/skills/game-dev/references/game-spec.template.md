# GAME_SPEC.md template

Fill this in at the end of Phase 1 and write it to the project root as
`GAME_SPEC.md`. Every field comes from an actual answer the user gave — do
not invent or default a field silently; if something wasn't asked, go back
and ask it rather than guessing.

```markdown
# Game Spec

## Core loop
{One paragraph, in your own words, confirmed back to the user — what does
a player actually do, moment to moment?}

## Genre
{Their Round 1 answer, verbatim or close to it. If freeform, quote their
description rather than forcing it into a bucket.}

## Platform target
{Desktop / Mobile / Both — and if Both, note any platform-specific
differences already known, e.g. "touch controls overlay on mobile only."}

## Art approach
{Placeholder (shapes) / Placeholder (Kenney.nl pack) / Pixel art / Vector /
User-supplied assets}

## Scope
{Quick prototype / Full small game — this drives the Phase 6 done-criteria.}

## Genre-specific answers
{Every Round 2 question and answer, as a bullet list. Keep the user's
actual wording where it matters (e.g. "floaty" vs "snappy" jump feel).}

## Explicit non-goals
{Anything the user ruled out or that's clearly out of scope for this pass —
optional, but useful to prevent later scope creep arguments.}
```

Update this file if the user changes their mind mid-project — it should
always reflect the current, real target, not the day-1 answers if they've
since changed.
